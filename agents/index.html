CBT Cards / For AI assistants

Give an assistant a source it can inspect.

CBT Cards publishes practical reflection resources in human-readable and machine-readable forms. An assistant can discover a relevant card, guide, or worksheet, check its language and publication status, preserve its source and safety context, and present it without needing access to a user's CBT Cards account or private journal.

What this interface is for

Use the public agent resources when an assistant needs to find, explain, cite, translate, or render CBT Cards material. The public interface is read-only. It does not connect to a user's app data, journal, check-ins, backups, or account.

The project deliberately keeps ordinary web pages as the human source of truth and publishes structured representations alongside them. Integrations should prefer the smallest interface that solves the task rather than loading the entire corpus for every request.

Recommended consumption flow

  1. Discover available resources through llms.txt or data/catalog.json.
  2. Choose a reviewed learning page, published toolkit record, or worksheet definition that fits the user's request.
  3. If a language is requested, check human language status, data/locales.json, and any matching record in data/translations.jsonl.
  4. Preserve the canonical URL and stable source ID when one is available.
  5. Check publication status before presenting raw toolkit material or a localized record as CBT Cards-published content.
  6. Keep the resource's safety scope and privacy behavior intact when summarizing, translating, or rendering it.

Choose the smallest useful interface

  • llms.txt: compact discovery index for the public resource surface.
  • llms-full.txt: extended source-priority, language, release, and safety guidance.
  • JSON catalog: stable resource IDs, canonical URLs, formats, locale metadata, and schema_url where applicable.
  • Curated JSONL: self-contained reviewed English source records for learning resources and published toolkit records.
  • Language status page: human-readable source, pilot, planned, reviewed, and published counts.
  • Locale registry: source, pilot, and planned language status.
  • Translation overlays: localized records keyed by stable resource ID, with explicit translation, review, publication, and source-snapshot status.
  • Worksheet definitions: ordered form definitions, canonical links, safety scope, and privacy behavior.
  • Toolkit review overlay: explicit CBT Cards publication status keyed by stable source record ID.
  • JSON Schema manifest: versioned contracts for CBT Cards-owned JSON/JSONL formats.
  • Changelog JSON: scoped public release provenance.
  • SKILL.md: latest portable instructions for assistants that support file-based skills.

Languages and translation status

English is currently the source language for the curated knowledge dataset. Russian is a pilot locale with machine-readable drafts for all 12 records in the current curated knowledge set; none is currently human-reviewed or published. German is planned and currently has no translation records.

A machine translation draft is deliberately not treated as a published CBT Cards localization. A localized record becomes official public CBT Cards content only after separate human language and editorial review, an explicit published status, and a canonical CBT Cards URL. Until then, an assistant can translate the canonical English resource for a user, but that translation belongs to the assistant rather than to CBT Cards.

Each translation records the review date of the source-language record it was based on. Repository checks reject a translation when that source snapshot no longer matches the current English record.

Published localized records are generated from reviewed translation data at /<locale>/resources/<resource_id>/. Locale-level public_html allows gradual publication: reviewed published records can coexist with machine drafts, which remain unpublished.

Human pages remain canonical

Structured data exists to make the same material easier for software to consume, not to create a second editorial universe. When a record has a canonical public page, keep that URL attached to the answer. For conceptual explanations, prefer reviewed pages in the learning library. For practical exercises, prefer published toolkit resources or worksheet definitions.

Toolkit publication status

Before presenting a raw source record as CBT Cards-published content, consult data/toolkit-review.json. Any unlisted source record defaults to unreviewed and source_only. reviewed_for_publication is editorial and safety review for public web use, not clinical validation or evidence of efficacy.

Versioned data contracts

Use schemas/index.json to discover contracts for CBT Cards-owned machine-readable resources, including the locale registry and translation records. The schemas describe portable field-level structure. Purpose-specific repository checks still enforce semantic invariants such as canonical targets, translation source snapshots, ordered worksheet fields, publication-set alignment, and privacy wording.

Printable worksheet interface

The public worksheets have no submit action. Text entered there remains in the current browser page unless the user independently prints or saves it. If an assistant renders a form from data/worksheets.json, preserve field order, labels, canonical URL, safety scope, and privacy behavior.

Versioned skills

The unversioned SKILL.md is a moving alias. For reproducibility, resolve manifest.json and pin the immutable version it identifies. Consumers that do not support file-based skills can use the same public pages and datasets directly.

Release provenance

Use the public changelog or data/changelog.json for website, dataset, translation, schema, worksheet, and agent-interface changes. A public-site release is not evidence that a new Android or iOS version shipped.

Use it safely

  • Do not claim access to a user's private CBT Cards data. Public agent resources contain public content only.
  • Do not infer diagnosis or clinical meaning from journal text, worksheet answers, mood, stress, energy, or toolkit wording.
  • Do not present a machine translation draft as reviewed or published CBT Cards content.
  • Do not infer publication approval from raw-corpus presence.
  • Do not equate editorial publication review with clinical validation.
  • Do not turn a short public exercise into individualized treatment instructions.
  • CBT Cards is for general wellness and self-reflection, not diagnosis, treatment, emergency support, or a substitute for qualified professional care.
