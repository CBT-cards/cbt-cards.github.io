Website localization policy

What languages this website actually publishes today, and what must happen before another locale becomes public.

Current website language

The public website at cbt-cards.github.io currently publishes one locale: English (en). English pages use the root URL structure rather than an /en/ prefix.

The machine-readable source of truth is data/locales.json.

This does not define mobile-app languages

The website locale registry describes this website only. It must not be used to infer which languages are currently available in the Android or iOS application. App-language claims require separately verified product or store release information.

Why there is no hreflang yet

Only one web locale is published, so the site does not currently emit hreflang alternates. Adding English-only hreflang markup would not create another language version; it would mostly create more markup for humans to maintain, a beloved industry pastime.

Requirements before a second web locale ships

  • Give every translated page a stable locale-specific URL.
  • Keep each localized page self-canonical.
  • Add self-referencing and reciprocal hreflang links between locale counterparts.
  • Add x-default where a global/default entry point is appropriate.
  • Update sitemap, locale registry, resource catalog, agent indexes, and internal navigation in the same release.
  • Preserve authoritative source links, safety wording, privacy boundaries, and resource provenance.

Health-adjacent translation review

Machine translation may assist drafting, but it is not sufficient publication review for health-adjacent learning pages, worksheets, or curated toolkit content. Those translations require human review before publication and must then enter the normal editorial freshness process.

Right-to-left locales

If a future locale uses a right-to-left script, localized HTML must declare dir="rtl" and receive layout review. Direction is a content-layout property, not merely a string substitution problem.

For agents and tooling

Use the locale registry for website-language claims. Do not merge website locale status with mobile-app language support, historical release notes, or unverified external metadata.
