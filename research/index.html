CBT Cards / Research

Test the assistant, not just the prompt.

CBT Cards publishes a small evaluation set for checking whether an assistant chooses the right public resource, preserves review and localization status, respects private-data boundaries, and knows when not to route a person into a reflection exercise.

Starter set: 24 cases, 7 categories

The first dataset contains 24 hand-authored scenarios across retrieval, learning, worksheets, localization, publication boundaries, privacy, and safety. Each case records an expected route, acceptable stable resource or source IDs, semantic checks, prohibited claims, and a rationale.

Read the JSONL cases · View the versioned schema

What the cases test

  • Resource selection: choose a published card when the user wants a short practical prompt.
  • Learning vs exercise: answer conceptual questions from reviewed learning pages instead of mechanically routing every request to a card.
  • Worksheet routing: choose the structured browser worksheet and preserve field order when a form is requested.
  • Localization: distinguish an official published localization from a machine draft or a translation produced by the host assistant.
  • Publication boundaries: keep raw protocol records source-only unless CBT Cards explicitly reviews and publishes them.
  • Privacy: do not claim access to a user's private journal, check-ins, backups, or account data through the public resource interface.
  • Safety abstention: preserve the general-wellness boundary and do not substitute a reflection card for the host platform's immediate-safety handling.

What this dataset does not claim

There are no public model scores in this release. The cases define evaluation targets; they do not pretend that a model was benchmarked merely because a JSONL file exists. The set is also not a clinical safety benchmark, diagnostic test, or proof that an assistant is appropriate for mental-health care.

The expected checks are intentionally semantic rather than exact-string answers. A useful evaluator should test whether the response preserves the relevant source and boundary, not whether it reproduces one preferred sentence.

Versioning and reproducibility

Cases use stable IDs such as eval-retrieval-worry-box. Resource expectations use the same stable catalog IDs and raw source IDs used elsewhere in CBT Cards. The repository validator rejects unknown IDs, missing category coverage, invalid source-only routes, localization expectations that conflict with published translation state, and evaluation metadata that drifts from the public catalog.

Meaningful changes to the case format require a new versioned schema URL rather than silently changing the contract. Dataset additions can extend the same v1 record shape while keeping existing case IDs stable.

Research direction

This starter set is deliberately small enough to inspect. Future releases can add multilingual fidelity cases, adversarial publication-status cases, retrieval ambiguity, source-update regressions, and recorded model runs with explicit model/version/date metadata. Those results should be published separately from the test cases so the benchmark does not grade itself, a surprisingly popular human tradition.
