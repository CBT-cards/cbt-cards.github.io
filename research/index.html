CBT Cards / Research

Test the assistant, not just the prompt.

CBT Cards publishes inspectable evaluation cases and reproducible baselines for checking whether an assistant chooses the right public resource, preserves review and localization status, respects private-data boundaries, and knows when not to route a person into a reflection exercise.

Starter set: 24 cases, 7 categories

The first dataset contains 24 hand-authored scenarios across retrieval, learning, worksheets, localization, publication boundaries, privacy, and safety. Each case records an expected route, acceptable stable resource or source IDs, semantic checks, prohibited claims, and a rationale.

Reproducible baselines

The repository now records two deterministic, non-model baselines in data/agent-eval-runs.jsonl. Both are regenerated from the case dataset by scripts/run_eval_baselines.py; CI rejects the checked-in run records if they differ from the code or from the current eval dataset hash.

  • null-route-v1: always declines to route to a resource. It gets 1/24 routes correct, 0/19 target selections, 0/4 locale behaviors, and 1/7 boundary routes. This is the intentionally weak floor.
  • deterministic-contract-router-v1: a small keyword router using only user_message. On the current starter set it gets 24/24 routes, 19/19 target selections, 4/4 locale behaviors, and 7/7 boundary routes.

The second baseline's perfect score is not evidence of general assistant quality. It is a contract/harness baseline built around the current small routing taxonomy. Its job is to prove that the cases, scoring fields, stable IDs, hashing, and result serialization can reproduce a known result before model runs are added.

What the cases test

  • Resource selection: choose a published card when the user wants a short practical prompt.
  • Learning vs exercise: answer conceptual questions from reviewed learning pages instead of mechanically routing every request to a card.
  • Worksheet routing: choose the structured browser worksheet and preserve field order when a form is requested.
  • Localization: distinguish an official published localization from a machine draft or a translation produced by the host assistant.
  • Publication boundaries: keep raw protocol records source-only unless CBT Cards explicitly reviews and publishes them.
  • Privacy: do not claim access to a user's private journal, check-ins, backups, or account data through the public resource interface.
  • Safety abstention: preserve the general-wellness boundary and do not substitute a reflection card for the host platform's immediate-safety handling.

What the numbers do not measure

The deterministic baselines do not grade free-form explanation quality, empathy, factual completeness, clinical suitability, or real-world model behavior. Boundary accuracy here means that the structured router chose the expected boundary route. A future model run must record its own model/provider/version and evaluator metadata rather than inheriting a deterministic baseline score.

The expected case checks are intentionally semantic rather than exact-string answers. A useful evaluator should test whether the response preserves the relevant source and boundary, not whether it reproduces one preferred sentence.

Versioning and reproducibility

Cases use stable IDs such as eval-retrieval-worry-box. Resource expectations use the same stable catalog IDs and raw source IDs used elsewhere in CBT Cards. Every run records the SHA-256 of the exact eval dataset bytes it used, so results cannot silently float onto a changed test set.

Meaningful changes to the case or run format require a new versioned schema URL rather than silently changing the contract. Dataset additions can extend the same v1 case shape while keeping existing IDs stable.

Citation and archival provenance

The repository includes a root CITATION.cff using Citation File Format 1.2.0, with CBT Cards described as a dataset and MetalHatsCats as the authoring entity. No DOI is claimed yet. A DOI should be added only after an archive actually assigns one to a release.

Research direction

Next useful additions are held-out paraphrase cases, multilingual fidelity grading, adversarial publication-status cases, source-update regressions, and actual model runs with explicit provider/model/version/date and evaluator metadata. Model results should stay separate from the test cases so the benchmark does not grade itself, a surprisingly durable human tradition.
