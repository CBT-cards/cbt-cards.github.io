CBT Cards / Research

Test the assistant on wording it did not memorize.

CBT Cards publishes inspectable evaluation cases, reproducible deterministic baselines, a separate held-out challenge set, and an isolated execution path for recording real model runs with dataset, prompt, skill, runtime, model, response, and evaluator provenance.

Starter set: 24 cases

The starter dataset covers retrieval, learning, worksheets, localization, publication boundaries, privacy, and safety. Each case records an expected route, stable resource or raw source IDs, semantic checks, prohibited claims, and a rationale rather than one exact reference answer.

Starter cases · Case schema · Starter runs

Starter baseline: useful, but friendly

deterministic-contract-router-v1 is a small keyword router that reads only user_message. On the starter set it reaches 24/24 routes, 19/19 target selections, 4/4 locale behaviors, and 7/7 boundary routes. The intentionally weak null-route-v1 floor reaches 1/24 routes.

The perfect starter score is a harness result, not evidence of general assistant quality. A router built around familiar wording can look rather competent when the examination politely repeats its study guide.

Held-out challenge: 12 new cases

The challenge set was authored separately with paraphrased and adversarial wording across the same seven categories. The deterministic router was not changed after challenge authoring before its result was recorded.

  • Same deterministic router: 1/12 routes, 0/10 target selections, 0/1 locale behaviors, 1/3 boundary routes.
  • Null route floor: 0/12 routes, 0/10 targets, 0/1 locale behaviors, 0/3 boundary routes.

The drop from 24/24 to 1/12 is the point of the held-out layer. It demonstrates brittleness instead of hiding it behind the starter score.

Protocol for real model runs

The repository has a two-stage protocol for evaluating ChatGPT, API models, OpenClaw, Hermes, or another assistant runtime without exposing benchmark answers during generation.

  1. Generate first. The model receives the case user_message, the normal public CBT Cards resources/runtime being tested, and the fixed model-run prompt v1. Benchmark-only expected fields remain hidden.
  2. Score later. After all responses are captured, evaluate_model_run.py reads the expected fields and deterministically scores route, exact target IDs, locale behavior, and boundary routing.

Each response uses the model-response contract. A published run uses the model-run contract and records provider, model, exposed snapshot/version, runtime, execution timestamp, prompt SHA-256, dataset SHA-256, evaluator version, raw answer text, answer hash, and per-case routing results.

Executable isolated OpenAI path

The first provider adapter is run_model_openai.py. It gives each API request the fixed evaluation prompt, the current public CBT Cards skill, and exactly one case field: user_message. Web search is restricted to the CBT Cards public domain and the routing envelope is requested as strict structured JSON.

Generation and scoring remain separate processes. score_model_execution.py converts an execution artifact into the neutral scored run, and check_model_run_candidate.py verifies prompt/dataset/skill/response provenance and refuses to treat v1 as semantically scored.

A manual GitHub Actions workflow, Run isolated CBT Cards model eval, can run either starter or challenge data in a fresh process using repository secret OPENAI_API_KEY once that workflow exists on the repository default branch. It uploads the execution manifest, raw response JSONL, and scored run JSON as an Actions artifact. It does not commit a public benchmark result automatically.

The full rules are in MODEL_RUN_PROTOCOL.md. Normal PR CI exercises input-isolation plus the complete post-generation scoring/candidate pipeline with a synthetic fixture; that fixture is not a model result.

What v1 scores, and what it does not

The deterministic model-run evaluator scores routing metadata only. It does not automatically grade empathy, prose quality, factual completeness, clinical suitability, the case expected_checks, or prohibited-claim compliance. Those dimensions require a separately declared semantic review method.

This separation matters: a route can be correct while the prose is poor, and polished prose can still use the wrong source or cross a publication/privacy boundary.

No model score yet

No LLM or hosted-assistant score is currently published. The isolated execution workflow is defined and CI-validated, but its manual Actions entry point is intended for use after the workflow is present on the default branch. A real result should then be generated in a fresh process with its own provider credential and inspected before publication. Deterministic baselines and CI fixtures must not be relabeled as model results.

Research direction

The next useful result is a first clean artifact-only model execution on starter and untouched challenge data, followed by a separately versioned semantic-review protocol for prohibited claims, source fidelity, and answer quality. Multilingual fidelity can then be evaluated without quietly converting translation drafts into official content.
